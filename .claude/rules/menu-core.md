# `packages/menu-core` и `packages/food-data` — движок меню и данные блюд

## Чистота и детерминизм

- `menu-core` — чистый TypeScript: без React, DOM, сети, ИИ, `Date.now()` и `Math.random()`. Время и случайность — только
  параметрами (`today`, `seed`). Один и тот же вход и `seed` дают тот же план, байт в байт.
- Код работает и в Web Worker (сайт), и в Node (тесты, симуляции, инструменты Кики). Импорты из `apps/*` запрещены.
- Операции не меняют вход: каждая возвращает новый `Plan` и `Diff`.
- Ошибки ввода — явным результатом (`{ ok: true, value } | { ok: false, error }`), не исключениями.

## Правила (DSL)

- Ограничения и предпочтения — данные на общем DSL (`menu-core`, интерфейс, инструменты Кики используют одну схему zod).
- Безопасность выше вкуса: аллергены, следы, диеты и пороги из `nutrition-core` — жёсткие фильтры, а не штрафы. Ни одна
  оценка и ни одна просьба пользователя не проводит блюдо сквозь жёсткий фильтр.
- Каждое правило и порог — со ссылкой на источник (R01–R20) в комментарии или в данных; новые числа проверяет
  `science-fact-checker`.
- Каждый выбор объясним: движок возвращает причины, а тексты собираются из них.

## Происхождение данных

- `food-data` собирают только скрипты: USDA SR Legacy, этикетки с указанием страницы. Модель не пишет и не правит цифры.
- У каждого значения есть происхождение: источник, дата, способ расчёта. Без источника значение не попадает в сборку.
- Нутриенты показываются как оценка (±10–20 %). Единицы — в именах полей (`energyKcal`, `proteinG`, `sodiumMg`).
- Схема данных версионируется; размер чанка `food-core` держим в бюджете (≤ 60 КБ gz).

## Тесты

- Юнит-тест на каждое правило и алгоритм; покрытие строк ≥ 90 %.
- Свойства (fast-check): 0 нарушений безопасности на 5 000 персон; детерминизм; план всегда проходит валидатор.
- Производительность `generate()`: ≤ 1,5 с на ноутбуке команды, ≤ 3 с при 4× замедлении CPU.
- Большие данные проверяй `node -e` или `jq`: файлы данных целиком не читать.
