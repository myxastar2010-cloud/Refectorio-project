# Фото блюд и иконки теста — откуда и на каких условиях

Игра «Выберите блюдо» показывает настоящие фотографии блюд. Кода в них нет, а условия использования у сервисов
фотографий строгие, поэтому здесь записано, что мы делаем и почему. Список авторов — [photo-credits.md](photo-credits.md).

## Почему файлов фото нет в репозитории

- **Unsplash** требует показывать фото по его собственным ссылкам (`images.unsplash.com`, «хотлинк») — так сервис
  считает просмотры для авторов ([правила API](https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines),
  [условия API](https://unsplash.com/api-terms)). Скачивать и выкладывать копии у себя нельзя.
- **Pexels** разрешает бесплатное использование, но запрещает распространять копии фото «сами по себе» — даже
  уменьшенные или обрезанные ([лицензия Pexels](https://www.pexels.com/license/)). Публичный git-репозиторий — это и
  есть распространение копий.

Поэтому в git лежат только **метаданные**: `packages/taste-core/data/photo-manifest.json` (какое фото у какого блюда,
автор, ссылки, точка кадрирования, средний цвет, blurhash-заглушка) и его облегчённая копия для сайта
`photo-runtime.json`. Ни файлов фото, ни ключей API в репозитории нет (pre-commit проверяет ключи: `scripts/check-secrets.mjs`).

## Unsplash — что мы соблюдаем

| Правило Unsplash API | Как сделано |
|---|---|
| Показывать фото по ссылкам из `photo.urls` и не убирать параметр `ixid` | Карточка берёт `urls.raw` и добавляет только параметры размера и кадра (`w`, `h`, `fit=crop`, `crop=focalpoint`, `auto=format`) |
| Вызывать `links.download_location`, когда фото выбрано для использования | `scripts/photos/finalize.mjs` вызывает его один раз для каждого выбранного фото и записывает дату в манифест |
| Подписывать автора и Unsplash ссылками с `utm_source=refectorio&utm_medium=referral` ([правило подписи](https://help.unsplash.com/en/articles/2511315-guideline-attribution)) | Строка «Фото: автор · Unsplash» под каждой карточкой и [photo-credits.md](photo-credits.md) |
| Держать ключ в секрете | Ключ читают только скрипты подбора (переменная окружения или папка `.secrets/` вне git); в браузер он не попадает — сайт к API не обращается вовсе (CSP: `connect-src 'self'`) |
| Демо-режим — 50 запросов в час ([документация](https://unsplash.com/documentation)) | Подбор и «отметки скачивания» сами ждут следующего часа |

## Pexels — если появится ключ

Сейчас Pexels не выдаёт новые ключи ([страница API](https://www.pexels.com/api/)), поэтому все фото — с Unsplash. Конвейер для Pexels готов: фото
скачиваются при сборке (`scripts/photos/materialize.mjs`) в папку, которой нет в git, обрезаются до 3:4 и
отдаются с самого сайта; подпись «Фото: автор · Pexels» и ссылка на Pexels обязательны.

## Если фото не открываются

Из некоторых сетей `images.unsplash.com` может не загружаться. Тогда карточка показывает размытую заглушку из
blurhash (цвета и композиция того же фото, хранится в манифесте) и название блюда. После двух неудачных фото подряд
игра перестаёт ждать сервис до перезагрузки страницы. Блюда без подобранного фото в игре не показываются,
но их вкус всё равно предсказывается по ответам.

## Иконки вопросов и вариантов

Иконки шагов теста (цель, тип питания, образ жизни и другие) нарисованы командой Modern Manifesto с помощью ИИ и
переданы в проект вместе с макетами. Скрипт `npm run quiz-icons` только обрезает их, чистит фон и сохраняет в AVIF и WebP
(`apps/web/src/assets/generated/quiz/`). Условия использования — те же, что у остальных материалов команды
(см. «Лицензия» в [README](../README.md)).

## Как заменить фото

Команда может закрепить своё фото за блюдом: id фото Unsplash в `packages/taste-core/data/photo-overrides.json`
(`{ "d_borscht": { "provider": "unsplash", "id": "…" } }`), затем `node scripts/photos/finalize.mjs` с ключом.
Порядок подбора целиком — в [architecture.md](architecture.md) (раздел о фото).
