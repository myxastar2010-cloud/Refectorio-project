# ADR 0011 · Фото блюд — копии на нашем сайте, без подписи в игре

- Статус: принято · 17.10.2026 · **заменяет ADR 0009** (в части показа фото; подбор и метаданные — как там)
- Связано: ТЗ этапа 3 (§4.1), решение D-048, `docs/photo-licensing.md`, `docs/photo-credits.md`,
  `scripts/photos/materialize.mjs`, `scripts/photos/files.mjs`, `apps/web/src/features/quiz/tinder/photos.ts`

## Контекст

На этапе 2 карточки игры показывали фото по ссылкам `images.unsplash.com` (хотлинк) с подписью «Фото: автор ·
Unsplash» под карточкой — так требуют правила Unsplash API для приложений, которые ищут фото через API. Команда
попросила убрать подпись из игры. Кроме того, у хотлинка три минуса: из части российских сетей CDN Unsplash (Fastly)
открывается медленно или не открывается; посетитель отдаёт свой IP-адрес стороннему сервису; CSP сайта приходится
открывать для чужого хоста.

## Решение

1. **Фото раздаёт наш сайт.** При каждой сборке (`prebuild`, также в CI, на Render и в Pages) скрипт
   `materialize.mjs` скачивает выбранные фото с CDN (w = 1920) в папку `.cache/dish-photos/` (её нет в git), режет
   до 3:4 вокруг сохранённой точки интереса и пишет 480/720/960 px в AVIF и WebP плюс одну маленькую (64 px)
   заранее размытую копию для описания блюда. Готовые файлы копируются в `apps/web/public/dish-photos/` (тоже вне
   git) и уходят на хостинг вместе с сайтом. **В репозитории фото по-прежнему нет.**
2. **Имена файлов** — `<провайдер>-<id>-f<x>x<y>-v<версия>-<ширина>.<формат>`: фото, кадр и версия конвейера.
   Другой кадр или другие настройки сжатия — другое имя, поэтому файлы кэшируются на год (`immutable`). Браузер
   строит адреса сам по `photo-runtime.json` (поля `provider`, `id`, `focal`, `avgColor`, `blurhash`), отдельный
   индекс не нужен; одно правило в `files.mjs` и `taste-core/src/photos.ts`, тест следит, чтобы они совпадали.
3. **Подписи в игре нет.** Фото используются по [лицензии Unsplash](https://unsplash.com/license): копировать,
   изменять и показывать можно без указания автора. Авторы перечислены в `docs/photo-credits.md`, ссылка — в
   карточке «О проекте» → «Подробнее» → «Авторы фотографий».
4. **CSP** — `img-src 'self' data:`: сайт не обращается ни к одному стороннему хосту.
5. **Надёжность сборки.** Готовые файлы кэшируются по хэшу манифеста (повторная сборка без изменений — доли секунды).
   Сборка для публикации падает, если не хватает больше 5 % фото; `npm run dev` (`--quick`) никогда не падает и
   сразу сдаётся, если CDN недоступен, — тогда игра показывает размытые заглушки из blurhash с названием блюда.
6. **Обратимость.** Флаг сборки `PHOTO_HOSTING=unsplash` возвращает хотлинк с подписью (сайт читает полный манифест);
   для Render нужно ещё вернуть `https://images.unsplash.com` в `img-src` в `render.yaml`. По умолчанию — `self`.

## Отступление от правил Unsplash API (D-048)

Фото найдены через Unsplash API (для всех 171 вызван `download_location`). Правила API просят приложения показывать
фото по ссылкам сервиса и подписывать автора. Мы показываем скачанные копии по лицензии Unsplash и без подписи в
игре — **сознательное отступление по просьбе команды.** Что можно сделать, если команда передумает: маленькая
подпись внутри описания блюда (§5 этапа 3) или флаг `PHOTO_HOSTING=unsplash`.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Хотлинк с подписью (ADR 0009) | Команда попросила убрать подпись; зависимость от CDN, недоступного из части сетей РФ; IP посетителя уходит третьей стороне |
| Хотлинк без подписи | Нарушает правила API сильнее, чем копии по лицензии, и не решает проблему доступности |
| Положить фото в git | Публичный репозиторий распространял бы копии «как набор фото» — лицензия Unsplash запрещает собирать из них похожий сервис; репозиторий стал бы тяжёлым |

## Последствия

- Сборка на Render скачивает и сжимает 171 фото (время чистой сборки — в отчёте этапа 3); GitHub Actions кэшируют
  `.cache/dish-photos`.
- Сайт весит больше (~ 70 МБ фото на хостинге), но каждый посетитель грузит только показанные карточки (≈ 30–60 КБ
  на карточку в AVIF) и маленькие размытые копии (≈ 1 КБ).
- Политика приватности стала проще: фото — с нашего сайта, сторонним сервисам ничего не передаётся.
