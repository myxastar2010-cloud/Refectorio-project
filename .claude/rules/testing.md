# Тестирование

## Юнит (Vitest 5)

- Тест лежит рядом с кодом: `foo.ts` → `foo.test.ts`. Корневой `vitest.config.ts` собирает проекты всех пакетов.
- Чистые функции тестируем на эталонных примерах из первоисточников (с комментарием-ссылкой), граничных значениях
  и свойствах (монотонность, неотрицательность).
- `packages/nutrition-core`: покрытие ≥ 95% строк, модуль `guardrails` — 100% веток. Порог зашит в конфиг — CI упадёт.
- Никаких снапшотов вместо проверок чисел.

## E2E (Playwright 1.63)

- Файлы — `apps/web/e2e/*.spec.ts`. Три браузера: Chromium, Firefox, WebKit; мобильная эмуляция — отдельные проекты.
- Детерминизм: режимы `?seed=123`, `?freeze=1`, `?pose=design` (только по параметру адреса).
- Локаторы — по ролям и доступным именам (`getByRole`), а не по классам.
- Анимации ждём по состоянию (атрибуты `data-scene`, `aria-hidden`), а не `waitForTimeout`.
- Доступность — `@axe-core/playwright` на каждой сцене и в диалоге: 0 серьёзных нарушений (исключение по контрасту задокументировано).

## Lighthouse CI

- Бюджеты (десктоп): Performance, Accessibility, Best Practices, SEO ≥ 0,95; LCP ≤ 2,0 с; CLS ≤ 0,02; TBT ≤ 150 мс.
- Мобильный профиль: Performance ≥ 0,85.

## Правила

- Тест, который падает «иногда», — это баг: чинить причину, а не добавлять повторы.
- На Windows скрипты кросс-платформенные: без `rm -rf`, `export`, `&&` внутри `package.json` там, где можно обойтись Node-скриптом.
