# ADR 0015 · Данные блюд меню: пакет `food-data`, состав из USDA с потерями при готовке

- Статус: принято · 03.11.2026 (этап 4, фаза 2)
- Связано: ТЗ этапа 4 (`00_Главное.md` §5.1, `03_Фаза-2_Наука-и-данные.md` §3–§8), ADR 0008 (каталог и модель вкуса),
  `packages/food-data`, `research/R17`–`R18`, `research/fact-check-food-data.md`, решения D-073…D-080,
  публичное описание — [«Как мы считаем состав блюд»](../science/dish-composition.md)

## Контекст

Меню (фаза 3) собирает приёмы пищи из ролей (основное, суп, гарнир, хлеб, напиток…), фильтрует по аллергенам, диетам
и правилам безопасности и считает дневные суммы — не только КБЖУ, но и натрий, сахара, кальций, железо, кофеин, воду.
На этапе 3 у 186 блюд игры были рецепты и КБЖУ (`taste-core/data/dish-nutrition.json`, карточки игры). Не хватало:
микронутриентов, потерь при готовке, простых позиций («Хлеб с маслом», «Чай»), ролей, флагов безопасности, следов
аллергенов. ТЗ оставило выбор: новый пакет или расширить `taste-core/data`.

## Решение

1. **Новый пакет `packages/food-data`.** `taste-core` остаётся каталогом игры и моделью вкуса; у полей блюд игры
   (название, приёмы пищи, аллергены, вкусовые признаки) источник один — каталог. `food-data` добавляет то, что нужно
   меню. Чанк игры не везёт данные меню, и наоборот.
2. **Только скрипты.** `npm run food-data` собирает данные из архива USDA SR Legacy и таблицы сохранности USDA Release 6
   (`.cache/usda`), рецептов исследований (`refectorio-workspace/research/`) и авторских фактов (`data/src/items.json`,
   `texts.json`). Результат коммитится: исходники `data/src/{ingredients,retention,recipes}.json` и чанки браузера
   `data/food-core.json`, `data/food-text.json`. Сборка чанков — чистая функция `assemble()`: тесты пересобирают их из
   репозитория и сверяют (CI не нужен архив USDA). Файл сохраняет дату версии, пока не меняется его содержимое.
3. **Вектор из 34 нутриентов** в одном порядке (`NUTRIENTS`) — в чанке, в суммах `menu-core` и в инструментах Кики.
   Хранится значение на порцию, на 100 г выводится. `null` — «нет данных», никогда не 0: показатель блюда известен,
   если продукты со значением дают ≥ 97 % массы (без воды). Нули ставятся только биологические (клетчатка мяса, B12
   растений, витамин C круп).
4. **Готовка.** Код сохранности по группе продукта и способу нагрева (R18 §T3b); жир фритюра — по Богнару 2002 на всё,
   что в сковороде, вместе с водой теста и кляра (так считались числа карточек игры); жир запечённого мяса — по выходам
   USDA; вода порции — вес минус сухое вещество. КБЖУ блюд игры совпадают с карточками (тест).
5. **Российские продукты.** Строки без американского обогащения (мука, рис, макароны, молоко); натрий несолёных масла
   и творога — из несолёных строк USDA; продукты с этикеток (кефир, ряженка, творог, майонез, квас, кочуджан): КБЖУ —
   медиана этикеток Open Food Facts, остальное — ближайший аналог USDA (`approx`) или медиана этикеток, если она есть.
6. **Аллергены и диеты** выводятся из ингредиентов. Для блюд игры каталог объявляет аллергены сам, а сборка сверяет:
   аллерген рецепта, которого нет в каталоге, — проблема сборки (тесты её не пропускают); «веганское» блюдо с маслом —
   тоже. Отдельно хранятся
   **следы** покупных ингредиентов (R07 §7, принцип VITAL: только реальный риск) — их учитывает лишь «сильная
   реакция даже на следы»; класс рыбы по ртути (FDA/EPA 2021) и флаги безопасности (сырая рыба, сырое яйцо,
   непастеризованное, солёная рыба, сыровяленое мясо, сыры с плесенью, печень, вино в готовке).
7. **Два чанка.** `food-core` — короткие ключи, общая таблица ингредиентов, массивы нутриентов (бюджет ≤ 60 КБ gz,
   сейчас 28,6); `food-text` — название, «что в порции», длинное и короткое описание (≤ 35 КБ gz, сейчас 21,3).
   Рецепты для шагов готовки — отдельные ленивые чанки фазы 6.
8. **Канонические имена ингредиентов** (`research/stage-4-food-data/ingredient-names.json`, проверены вручную): меню,
   поиск и Кики показывают «кофе эспрессо», а формулировка рецепта («для пропитки») остаётся в рецепте.

## Альтернативы

- **Расширить `taste-core/data`** — отклонено: смешивает игру и меню, тесты и чанки обоих растут вместе.
- **Считать состав в браузере из SR Legacy** — отклонено: архив 5,8 МБ, расчёт и проверки нужны до выпуска.
- **FNDDS (готовые американские блюда)** — отклонено: рецепты не совпадают с русской кухней; оставлено для сверки.
- **Таблицы Скурихина как основа** — нет открытой машиночитаемой копии с понятной лицензией; используются для проверки.

## Последствия

- `menu-core` загружает `food-core` в воркере во время финала теста; `decodeFoodCore()` проверяет чанк схемой zod.
- Числа показываются как оценка ±10–20 %; известные ограничения перечислены в публичном описании (кальций творога и
  хлеба, витамин C картофеля, округление маленьких порций).
- Новая позиция: факты в `items.json`, рецепт в исследованиях, описание в `texts.json`, имя ингредиента в
  `ingredient-names.json` → `npm run food-data` (отчёт: `reports/stage-4/food-data-report.md`) → тесты
  `packages/food-data`: проблемы сборки, расхождение с карточками игры или бюджеты чанков их роняют.
