# ADR 0008 · Игра «Выберите блюдо»: байесовская модель вкуса и отбор карточек по BALD

- Статус: принято · 09.10.2026 (дополнено 11.10.2026)
- Связано: ТЗ этапа 2 (§9), исследование R15 (`refectorio-workspace/research/R15-taste-elicitation.md`), решение D-035,
  `packages/taste-core/`, отчёт симуляции `refectorio-workspace/reports/stage-2/taste-sim/`

## Контекст

Первый вопрос теста — игра: человек видит фото блюда и отвечает «нравится», «не нравится» или «пропустить». Нужно за
**10 решающих ответов** узнать вкус настолько, чтобы на этапе 3 меню состояло из блюд, которые человеку понравятся.
Данных о других людях нет (холодный старт), каталог — 186 блюд с описанием признаков: кухня, тип блюда, белок,
способ приготовления, основа, вкусы, текстура, насыщенность, острота, сладость, знакомость в России.

## Решение

1. **Модель.** Вероятность «нравится» = Φ(wᵀφ(блюдо)): φ — разреженный вектор признаков блюда, w — вкусы человека.
   Априор на w — гауссов, со структурой: похожие признаки (например, «говядина» и «свинина») связаны через общие группы,
   а средние взяты из данных о том, что едят в России (R15 §7). Каждый ответ обновляет апостериор приближением
   ADF (пробит), без итераций — < 5 мс на карточку.
2. **Пропуск — не ответ.** «Пропустить» не учит модель вкусу, а обновляет отдельную оценку «насколько человек
   осторожен с незнакомым» (неофобия, R15 §6): после 5 пропусков подряд показываются хорошо знакомые блюда.
3. **Отбор следующей карточки:** максимум BALD (сколько бит ответ скажет о вкусах, а не о шуме) × вероятность
   решающего ответа, с правилами: первые карточки — разных типов блюд, без двух похожих подряд, без повторов.
4. **Сессия детерминирована:** seed + список ответов → те же карточки; черновик восстанавливается повтором ответов,
   «Назад» отменяет последнюю карточку. Блюда без подобранного фото игре не показываются (их вкус всё равно
   предсказывается) — `createTasteSession(…, { hidden })`.
5. **Результат** — `TasteProfileV1` (`packages/contracts`): журнал ответов, апостериор, вероятность «нравится» для
   каждого блюда и уверенные подсказки (`avoidsMeat`, `avoidsFish`, `likesSpicy`…). Тест использует только
   `avoidsMeat`/`avoidsFish`, чтобы мягко подсветить вариант питания («Похоже, вам подходит…»), никогда не выбирая его сам.

## Проверка: симуляция 5000 игроков

Синтетические игроки сделаны **не по нашей модели** (архетипы, взаимодействия признаков, скрытые вкусы вне φ,
«странности» отдельных блюд, шумные ответы, пропуски по своей формуле), иначе проверка была бы круговой.

| Критерий ТЗ | Результат | Статус |
|---|---|---|
| AUC на незнакомых блюдах после 10 ответов ≥ 0,70 | 0,715 (0,709 / 0,721 при другом уровне шума) | выполнен |
| Прирост (AUC₁₀ − 0,5) / (AUC₃₀ − 0,5) ≥ 0,9 | 0,887 | не выполнен |
| Лучше каждой базовой стратегии с непересекающимися 95 % ДИ | лучше «случайной» и «неопределённости»; с «популярностью» и «охватом» интервалы пересекаются | не выполнен |

В парном сравнении на тех же игроках наш отбор достоверно лучше всех четырёх базовых (все 95 % ДИ разницы > 0).
Почему не дотянули и что пробовали — D-035: около половины разброса вкуса в симуляторе — скрытые предпочтения, которых
нет в описании блюд; ни один из проверенных вариантов (EPIG, просмотр вперёд, Лаплас, другие априоры) не дал
устойчивого выигрыша > 0,005.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Парные сравнения («что больше нравится») | Нет абсолютной шкалы, ответ тяжелее одного касания, не различает «нравятся оба» (R15 §9.2) |
| Коллаборативная фильтрация | Нет данных о других людях; появится как дополнительный априор, когда накопятся анонимные сессии |
| Только популярность | Мало информации за ответ; используется лишь как априор |
| Бандиты / Thompson sampling | Оптимизируют «покажи то, что понравится», а нам нужно узнать вкус |
| Эмбеддинги фото (Yum-me) | Нужна обученная сеть; позже — как дополнительные признаки |

## Последствия

- Число «10 ответов» — компромисс: модель продолжает учиться и дальше. Живая проверка на 15–30 людях (R15 §9.4) и
  ковариация априора, выученная на реальных ответах, — задачи этапа 3.
- `?taste=debug` показывает апостериор и топ-12 блюд «понравится / не понравится» после игры — для проверки командой.
- Каталог расширяется без изменения кода: id блюд постоянны, новые признаки встраиваются в φ автоматически.
