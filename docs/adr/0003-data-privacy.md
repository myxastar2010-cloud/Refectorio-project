# ADR 0003 · Данные и приватность: гостевой режим по умолчанию, Neon — только по желанию

- Статус: принято (реализация — этап 3) · 02.10.2026
- Связано: R12 (152-ФЗ), R08, `research/conflicts.md` C-01, решения D-009 и D-012

## Контекст

Вес, болезни, беременность и аллергии — **специальная категория** персональных данных (ст. 10 152-ФЗ): нужно отдельное
письменное согласие. Данные граждан РФ, если сохраняются на сервере, должны первично храниться в РФ (ст. 18 ч. 5).
Бесплатная БД Neon находится в США/ЕС. Для данных о здоровье несовершеннолетних нужно согласие законного представителя
до 18 лет (письмо РКН от 11.03.2022 № 08-15154).

## Решение

1. **Гостевой режим по умолчанию:** анкета, меню и дневник хранятся только в браузере (localStorage/IndexedDB).
   Сервер их не сохраняет и не логирует → продукт не становится оператором этих данных.
2. **Аккаунт — по желанию** (этап 3): Neon Postgres + Drizzle + Better Auth. В аккаунте — минимум данных, явное согласие на
   обработку данных о здоровье, экспорт и удаление в один клик. Пока БД вне РФ — в аккаунт **не** переносятся данные о здоровье
   без отдельного согласия; если проект станет «настоящим» — перенос БД в РФ (Yandex Cloud).
3. **Возраст:** 14–17 лет — только гостевой режим (D-009); хранение данных о здоровье на сервере — с 18 лет или с согласием
   родителя; 1–13 — семейный режим (решения принимает взрослый); < 1 года — вне продукта.
4. **Запросы к ИИ** — только обезличенные параметры (возраст, пол, цель, ограничения), без имени и контактов; промпты не
   привязываются к аккаунту и не хранятся дольше обработки запроса.

## Альтернативы

- Supabase (пауза проекта через 7 дней без активности), Neon Auth (меньше гибкости), Yandex Cloud YDB (данные в РФ,
  но нужен платёжный аккаунт) — оставлены как варианты для этапа 3.

## Последствия

- Карточка «Гарантия: сохранение ваших данных» на главной — правда по устройству продукта, а не обещание.
- Синхронизация между устройствами появится только с аккаунтом.
