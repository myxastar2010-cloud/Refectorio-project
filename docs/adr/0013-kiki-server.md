# ADR 0013 · Сервер Кики: Hono + SSE без состояния, инструменты в браузере, цепочка моделей NVIDIA

- Статус: принято (фаза 5 этапа 4) · 10.11.2026
- Связано: ТЗ `06_Задание-4/07_Кики.md` §2–§12, ADR 0002 (хостинг), 0003 (данные), 0005 (ИИ-шлюз), R20, D-108…D-112

## Контекст

Кики — ИИ-диетолог меню. Главный принцип проекта: **ИИ не считает цифры**. Меню, нормы и порции живут в браузере
(IndexedDB, D-062), движок `menu-core` работает в Web Worker. Ключ ИИ нельзя отдавать в браузер; хранить переписку на
сервере мы не хотим (152-ФЗ, R12) и не можем (бесплатный Render, D-007). Провайдер — бесплатный NVIDIA Build: условия
пробного доступа (v. 19.09.2025) — только оценка, без персональных и медицинских данных (§1.2, §2.6, §4.3).

## Решение

1. **`apps/api`** — Node 24 + Hono 4 (`@hono/node-server`), Render Web Service `refectorio-api` (Frankfurt, free).
   `GET /health` (версия, база знаний, модели, состояние провайдера), `POST /kiki/chat` → Server-Sent Events.
   Сборка — rolldown в один `dist/server.mjs`. Hono выбран вместо Fastify: меньше (≈ 14 КБ), Web-стандартные
   `Request/Response`, встроенные CORS, лимит тела и SSE.
2. **Без состояния.** Каждый запрос несёт окно сообщений (≤ 2 800 токенов, целые ходы, пары «вызов — результат»),
   память (сводка + факты) и сводку контекста (≤ 2k токенов, без возраста, роста, веса и здоровья). Старые ходы
   сворачивает в память сам сервер одним вызовом по строгой схеме, когда клиент присылает `fold`.
3. **Протокол** (`kiki-core/protocol.ts`): `status`, `text-delta`, `text-reset`, `server-tool`, `ui`, `memory`,
   `continue`, `tool-call`, `final`, `error`. Клиентский инструмент завершает поток событиями `continue` (что добавить в
   историю) и `tool-call`; браузер выполняет его в воркере меню и шлёт следующий POST. ≤ 6 раундов инструментов за ход,
   бюджет хода 45 с (дальше модель отвечает без инструментов).
4. **Где работают инструменты.** Чтение и предложения — в браузере (`kiki-core/client` в воркере `menu-core`: у
   него план, данные блюд, профиль). `ask_choice` и `open_ui` обрабатывает сервер (это только интерфейс: без лишнего
   круга по сети). `kb_search` — сервер (BM25 по справочнику сайта и научным карточкам). Все аргументы проверяет zod;
   выдуманный id — ошибка, которую видит модель, а не догадка.
5. **Только предложения.** `propose_*` возвращает `previewId` + текст, написанный кодом, + числа движка. Меняет меню
   только пользователь кнопкой «Применить»; если меню успело измениться, операция пересчитывается на текущем меню.
6. **Проверка ответа** (`kiki-core/validate.ts`): каждое число с единицей должно найтись в результатах инструментов
   этого хода, сводке, базе знаний или словах пользователя (с округлением «как пишут люди», л ↔ мл, счётные ≤ 14);
   имена вендоров и моделей, диагнозы, дозировки лекарств и добавок, чужие ссылки, длина, язык. Провал — один
   исправляющий запрос без инструментов, затем безопасная фраза.
7. **Цепочка моделей** — переменная `AI_PROVIDERS` (`nvidia:<id>[?reasoning_effort=low]`, через запятую). 429 / 5xx /
   таймаут первого байта 20 с / пустой ответ → следующая модель; модель после 429 отдыхает 60 с. Если текст уже
   показан — ошибка с повтором (две модели в одном ответе не смешиваются). Вызовы инструментов, записанные моделью
   текстом (`[TOOL_CALLS]…`), распознаются и не мелькают в чате.
8. **Защита и приватность.** CORS — белый список (Render, Pages, localhost); без cookies; тело ≤ 256 КБ; лимиты по IP
   (20 ходов / 10 мин, 150 / сутки) в памяти; логи — только метрики (время, модель, токены, имена инструментов, коды
   ошибок), **никакого содержимого**. Ключ — только переменная окружения Render (`sync: false`), локально — через
   `scripts/secrets/read-key.mjs` (`npm run dev:api`).
9. **Выбор модели — по данным** (`npm run kiki:eval`, 91 случай, кэш на диске, ≤ 35 запросов/мин): GLM-5.3-Flash и
   DeepSeek V4.1 Flash на бесплатном NVIDIA не ответили ни разу за 150 с в трёх замерах (02.11, 10.11 ×2) — выбыли
   по доступности. Mistral Large 4 с `reasoning_effort=low`: инструмент за 1,4–2,4 с в пробе, 90 % проверок и 0
   провалов безопасности в первом прогоне. Сравнение на 40 случаях × 3 прогона (bakeoff-2, промпт p1.0, 11.11):

   | Модель | Все проверки | Инструмент + аргументы | Уточнения | Числа без опоры | p50 / p95, с | Ошибки связи | Русский |
   |---|---|---|---|---|---|---|---|
   | Mistral Large 4 (low) | 80,4 % | 89,1 % | 97,1 % | 0 | 13,9 / 83,7 | 5 | 4,47 |
   | Nemotron 3.5 Super VL | 82,6 % | 88,4 % | 98,6 % | 0 | 5,9 / 29,1 | 1 | 4,48 |

   Качество одинаковое (12 из провалов обеих — устаревшие ожидания набора, D-115), Nemotron в 2,4 раза быстрее и
   умеет картинки (анализы, фаза 7). **Порядок `AI_PROVIDERS`: Nemotron 3.5 Super VL → Mistral Large 4 (low)** (D-116).
   Пороги набора — по полному прогону основной модели (`reports/stage-4/kiki/eval-full-*.md`). Порог ТЗ p95 ≤ 8 с на
   бесплатной очереди NVIDIA недостижим ни одной моделью (D-115).

## Последствия

- Бесплатный экземпляр Render засыпает: сайт заранее «будит» `/health` при открытии меню, чат показывает «Кики
  просыпается… (до минуты)», после 65 с — «Кики сейчас недоступна» и что можно сделать без неё.
- Задержка бесплатной очереди NVIDIA непредсказуема (первый байт 0,2–55 с при одинаковых запросах): цель p95 ≤ 8 с
  на бесплатном уровне недостижима гарантированно — честно сказано в отчёте; для публичного запуска нужен платный
  провайдер (то же требуют условия NVIDIA Trial).
- Лимиты в памяти сбрасываются при перезапуске; при нескольких экземплярах понадобится общее хранилище.
- Переписка хранится только в браузере (`refectorio.chat`, стирается «Удалить мои данные»); в файл резервной копии
  пока не входит.
